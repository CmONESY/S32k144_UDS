## 1. 先把目标拆成 4 个能力

"识别色块并搬运到目标区域"= 下面 4 件事必须都能闭环，缺一件就跑不通：

| 能力 | 含义 | 参考文档是否覆盖 |
| --- | --- | --- |
| 走 | 底盘能直行、转弯、走指定距离/角度并停准 | 部分覆盖（电机+驱动+轮子） |
| 看 | 知道色块**在哪**（位置）和**是什么色**（类别） | 不覆盖（只有单点颜色传感器） |
| 抓 | 有执行机构把色块拿起来 | **完全缺失** |
| 放 | 把色块送到目标区并准确放下 | **完全缺失** |

参考文档给的是 2023 年**循迹小车**的物料单（Arduino Nano + L298N + TCRT5000 循迹 +
TCS230 颜色识别 + 轮子/万向轮/开关/马达支架）。它是"走"的底子，不是"抓取搬运"的底子。

## 3. 缺口清单

### 3.1 硬件缺口 — 必需（不做就没法完成目标）

| # | 缺什么 | 建议选型 | 解决哪个能力 |
| --- | --- | --- | --- |
| H1 | **抓取执行机构** | 舵机机械爪（MG90S/MG996R）+ 升降机构；或微型吸盘+气泵 | 抓 |
| H2 | **色块的"位置"来源** | 首选 OpenMV H7 / K210 / 树莓派+摄像头（串口输出色块坐标+颜色 ID）；预算受限则 TCS34725 阵列 + 二自由度云台扫描 | 看 |
| H3 | **行走闭环反馈** | 带 AB 相编码器的减速电机（或者霍尔编码器），接定时器正交解码 | 走 |
| H4 | **电源系统** | 2S/3S 锂电（7.4~11.1V）+ DC-DC 降压（12V→5V，**≥3A**）+ 电池电压检测分压 | 全部 |
| H5 | **底盘结构件** | 底板（亚克力/铝板）、舵机支架、爪/升降支架、铜柱+3mm 螺丝、扎带/魔术贴 | 抓/放 |
| H6 | **调试与下载工具** | S32K144 用板载 OpenSDA 或 J-Link/PE 调试器；USB-TTL 串口模块（看传感器数据）；万用表 | 全部 |

### 3.2 硬件缺口 — 推荐（决定稳定性和成绩上限）

| # | 建议 | 理由 |
| --- | --- | --- |
| H7 | 把 L298N 换成 **TB6612FNG** 或 DRV8871 | L298N 压降大、逻辑高电平门限约 2.3V，S32K144 是 3.3V I/O，临界；TB6612 省电且 3.3V 逻辑友好 |
| H8 | 加 **IMU（MPU6050/ICM20602，I2C）** | 无编码器时靠陀螺仪纠转角；有编码器时提升直线度 |
| H9 | 加 **ToF（VL53L0X，I2C）或超声波** | 对位目标区边界、防撞、定距第二来源 |
| H10 | 加 **限位开关 / 爪电流检测** | 判断"爪已夹紧/已降到底"，避免舵机堵转烧毁 |
| H11 | 多路 **50Hz 舵机 PWM** | 爪 + 升降 + 云台 = 2~3 路，各自独立供电 |
| H12 | 灰度/循迹阵列（TCRT5000 ×5） | 走到目标区后沿边线对位停放 |
| H13 | 场地用色块与标定板 | 提前统一色块尺寸、材质（哑光）、目标区标记方式 |

### 3.3 必须注意的电平与供电坑

- **TCS3200 的输出是 5V 推挽**，直接接 S32K144 的 3.3V 引脚会打坏 IO。要么加分压/电平转换，要么直接用 **TCS34725（I2C，3.3V 兼容，直接读 RGB）**。
- **舵机必须独立 5V 供电**，SG90 堵转电流可达 0.7A 以上，绝不能从 MCU 板取电，且**所有模块必须共地**。
- 电池端加电压检测（分压进 ADC），电压下降会让 PWM 调速和舵机力矩漂移，需要补偿或做低电报警。
- 电机电源与 MCU 电源之间加滤波（电感/大电容），否则电机启停会导致 MCU 复位。

### 3.4 软件/固件缺口

1. **电机控制**：方向 GPIO + PWM 调速；需要一路 PWM×2（左右轮 ENA/ENB），并处理"死区占空比"（占空比太低电机不转）。
2. **编码器测速与里程**：定时器正交解码 + 定时采样算速度/里程；定距停车、90° 转角。
3. **舵机驱动**：50Hz、0.5~2.5ms 脉宽 → 角度映射表 + 限幅保护（防堵转）。
4. **颜色/视觉数据接口**：串口协议（帧头 + 颜色 ID + dx + dy + 校验），RGB 白平衡标定流程。
5. **抓取动作时序**：接近 → 对准 → 下降 → 闭合 → 抬起 → 运送 → 放置 → 松开 → 退回。
6. **总状态机**：SEARCH → ALIGN → GRAB → CARRY → PLACE → RETURN，含超时/失败重试。
7. **调试手段**：串口打印关键变量（速度、颜色读数、状态），LED 做状态指示。

### 还差的外设（需要在 S32DS 配置工具里补）

| 待补外设 | 用途 | 备注 |
| --- | --- | --- |
| FTM 第二路以上 PWM | 左右轮 ENA/ENB 调速 | 现在只有 CH1，需要加通道 |
| FTM 正交解码（或输入捕获） | 编码器测速/里程 | S32K144 的 FTM 支持正交解码 |
| ADC | 电池电压、模拟灰度/颜色 | 需新增 ADC 配置 |
| I2C 或 SPI | IMU / ToF / OLED | 需新增配置 |

### MCU 资源够不够？

目标方案需要：4 路 GPIO（电机方向）+ 2 路 PWM（调速）+ 2~3 路 50Hz 舵机 PWM +
2 个定时器（编码器）+ 1 路串口（视觉）+ 1 路串口（调试）+ I2C（IMU）。

**S32K144 完全够用**（FTM 有多个实例和多通道），STM32F103C8T6 也够。
如果视觉算法放到 OpenMV/K210 上跑，主控只做运动+通信，两者都绰绰有余。

## 5. 主控选型：S32K144 还是 STM32？

| 维度 | 继续用 S32K144（现状） | 换 STM32（如 F103C8T6） |
| --- | --- | --- |
| 已有投入 | 工程、引脚、外设全配好了，**直接可用** | 板级/引脚/外设配置要重做 |
| 工具链 | S32DS 3.5 已装好，OpenSDA/J-Link 可下载 | 需 Keil/CubeMX + ST-Link |
| 资料与例程 | 车类教程少，遇到问题查资料慢 | 车类/循迹/平衡车资料海量 |
| 能力 | 够用（多 FTM、多串口） | 够用（多定时器） |

建议：**除非队友更熟 STM32，否则先在这块 S32K144 上把骨架跑通**，不要为了换而换。
真决定换，也先把"硬件方案和协议"定稳，再动代码。

## 6. 入手路线（按顺序做，每步都有可验收的结果）

### 阶段 0：把现有骨架跑起来（约 1 天）
- 编译下载 → 4 个 LED 能亮；按 KEY1/KEY5 有反应；串口能收到打印；舵机被 PWM 驱动转动。
- 学会在 S32DS 配置工具里"加一路外设 + 生成代码"，这是后面所有工作的前提。
- 验收：串口打印一行 `hello`，舵机在 0°/90° 之间来回。

### 阶段 1：单模块逐个打通（约 2~3 天，不要并行）
1. **电机**：先用 GPIO 让 L298N 正反转，再加入 PWM 调速；测出"最低能转的占空比"（死区）。
2. **舵机**：写 `set_servo_angle(deg)`，扫描 0/45/90/135/180，记录实际限位。
3. **颜色**：TCS3200 需要 S0/S1 定量程、S2/S3 切滤光片，输出是**频率**（要用输入捕获或脉冲计数测），串口打印 R/G/B 原始值；或直接换 TCS34725 用 I2C 读。
4. 验收：串口能看到红/绿/蓝色块读数明显分离，光照变化时读数稳定。

### 阶段 2：让车走准（约 3~5 天）
- 编码器测速 → 速度 PID 走直线；里程换算 → 走 50cm 误差 <2cm；陀螺仪/编码器配合转固定角度。
- 验收：连续 5 次直行 1m 偏离 <5cm。

### 阶段 3：让车"看见"色块（约 3~5 天）
- 先做简单版：云台 + 单点颜色传感器扫描，靠左右扫描找到色块方位（慢，但能验证流程）。
- 再做推荐版：OpenMV/K210 识别色块，串口发 `颜色ID + 中心坐标 + 面积`；主控据此对准。
- 验收：把色块放在视野任意位置，主控能收到正确的颜色和方向偏差。

### 阶段 4：抓取与放置动作（约 3~5 天）
- 调通爪的张开/闭合角度、升降高度，加限位开关或电流检测判断"夹住了"。
- 验收：手动摆好色块，车能一次完成 靠近→夹起→移到目标区→放下。

### 阶段 5：整合成状态机（约 3~5 天）
- 固化成状态机：`SEARCH → ALIGN → GRAB → CARRY → PLACE → RETURN`，加超时与重试。
- 验收：一次上电，全自动完成一个色块的搬运，重复 10 次成功率 ≥ 8 次。

### 阶段 6：场地标定与鲁棒性（比赛前一直做）
- 光照标定（白平衡/阈值随场地重标）、地面摩擦、电池压降对速度的影响、色块位置随机化。
- 验收：换场地后 30 分钟内完成标定并恢复成功率。

## 7. 建议的通信协议（主控 ↔ 视觉模块）

简单定长帧，便于解析和校验：

```
0xAA | 0x55 | color_id | dx_hi | dx_lo | dy_hi | dy_lo | area | checksum
```

- `color_id`：0=无目标，1=红，2=绿，3=蓝（按题目实际扩展）
- `dx`：色块中心相对画面中心的水平偏差（有符号），主控用它做转向控制
- `area`：色块面积，用来判断远近/是否进入抓取范围

先在串口调试助手里用假数据打通解析逻辑，再上真实视觉模块，能省掉一半调试时间。

## 8. 一页纸优先级

1. 电源与共地（H4）——所有问题的根源都是电。
2. 抓取机构（H1）——你的目标里最缺、最费结构件的部分，越早动手越好。
3. 色块位置来源（H2）——决定"看"的方案，越早定方案越好。
4. 编码器（H3）——决定"走"得准不准。
5. 阶段 0~1 先把现有 S32K144 工程的单模块验证做完，再买新硬件。
